Agentic Systems Design · Control Plane vs. Reasoning Plane

Orchestration Topology: Deterministic Backbone, Adaptive Agents

Pattern: Fixed DAG + Parallel Fan-Out / Fan-In (not an unconstrained hub-and-spoke loop). Code owns control flow & safety; Gemini 3.8 Flash owns reasoning & adaptation.

Deterministic & Fixed (Code Owns Safety)
  • Orchestration DAG: Fixed 3-stage fan-out/fan-in—no LLM inventing random subagents.
  • Routing & Budgets: Deterministic Startup vs. Non-Profit specialist roster; hard ≤ 2 Tavily tool cap in code.
  • Grounding Gate: Programmatic URL & host verification against [SRC-N] registry.
  • Browser Guardrails: SSRF blocklist, login/CAPTCHA halt, Semaphore(2), hard stop before Submit.
Probabilistic & Multimodal (Gemini 3.8 Flash)
  • Native PDF Ingestion: Extracts pitch decks & financial PDFs directly into intake & fact ledger.
  • Two-Phase Tool → Schema: Specialists decide if follow-up research is needed, then emit strict Pydantic JSON.
  • Vision + DOM Mapping: Reads live screenshots + DOM to fill any portal and flag missing EIN/UEI.
Judges often ask: "How did you architect the agentic system — is it hub-and-spoke, and what's deterministic vs probabilistic?" We deliberately avoided an unconstrained hub-and-spoke loop where an LLM invents ad-hoc subagents. Instead, we use a Deterministic Orchestrator with Parallel Fan-Out/Fan-In: green boxes are fixed code owning control flow, routing, tool budgets, citation verification, and browser safety (SSRF, login halt, hard stop before Submit). Purple boxes are probabilistic Gemini 3.8 Flash agents owning query planning, bounded follow-up research, structured extraction, and adaptive DOM-to-fact form filling.
